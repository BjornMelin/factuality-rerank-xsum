# Final Project Guidelines

## Assignment Details

Beyond programming assignments, **final project** = significant NLP implementation and/or application.

### Here's What to Expect

- Group **up to 3**; **solo** OK; collaboration encouraged.
- More members → **more total work** expected.
- Topic **within class scope**; need not mirror lecture.
- Turn in: **research-style write-up**, **short presentation**, **code**.

## Learning Outcomes

Assignment aligns with:

- **CLO 1:** Understand and describe multiple facets of linguistic phenomena related to natural language processing.
- **CLO 2:** Describe fundamental concepts, techniques, problems, and modern approaches in the domain of natural language processing (NLP).
- **CLO 3:** Understand the assumptions, strengths, and limitations of NLP and related deep learning techniques, and make appropriate decisions about application of techniques and solutions to NLP problems.
- **CLO 4:** Analyze textual data using a number of machine learning and deep learning-based NLP techniques.
- **CLO 5:** Demonstrate familiarity with and comprehension of existing NLP techniques for solving practical problems.
- **CLO 6:** Demonstrate an ability to stay current with a constantly evolving field: by developing a familiarity with the neural network architectures that underpin current state of the art, and an ability to seek out and understand new advances published in the field.
- **CLO 7:** Demonstrate expertise in using existing libraries and tools related to NLP work, along with an ability to familiarize oneself to new libraries and tools that are key to NLP practitioners as the domain evolves.

## Guidelines and Rubric

### Grading

**Much more work** than one assignment. Beyond code: **planning**, **research**, pipeline for data / experiments / plots / workflow. **Start early**; **ask questions**.

### Milestones

- **[1%] Project Proposal**
- **[0%] Milestone (optional)**
- **[99%] Write-Up and Final Presentation**

### Group Project Expectation

If **2 or 3** members: each owns **≥ one separate model** in experiments. Else **possible point loss**.

### Our Expectations of You

Grad-level: **seek help** when stuck. Support exists if you ask.  
Don’t wait for deliverable feedback to act. Formal option: **Milestone** section.

### Rubric Dimensions

Weak on any dimension → **much lower grade**. Bullets = typical pitfalls; projects vary -- use judgment.

#### Overall Themes (10%)

- Clear **problem statement**  
- **Novelty**  
- Prior work: who, what, your delta  
- Read, understood, **right** citations?

#### Crisp Objective (20%)

- **"How will I know success?"** → usually **metric**  
- Ties to problem -- why this objective?  
- **Clear baseline** (e.g. always predict majority class)  
- Field-standard objective? If not, why?

#### Methodology and Analysis (50%)

- Techniques fit problem?  
- First tries → learnings → improved iterations  
- Interesting patterns in data, model--data fit, losses / dynamics  
- Patterns vs papers? What did authors do?

#### Technical Communication (20%)

##### Primarily

- A **succinct and interesting presentation** explaining the key elements above
- A **well-organized paper**

##### Table Stakes

- Spell check  
- Proofread  

#### Volume of Work

Baked into other parts. Red flags: mostly others’ GitHub + clean Kaggle; only assignment notebooks on new data; for **3** people, each should show **~solo-project** effort.

### Rubric Scoring Levels

- **Missing:** 0%
- **Severe Issues:** 1% - 69%
- **Needs more work/thought:** 70% - 82%
- **Satisfactory:** 83% - 88%
- **Strong:** 89% - 94%
- **Near-publishable:** 95% - 100%

Expect **Strong** on most parts for most students.

### Project Scope and Ideas

**Open-ended**; **must be NLP.** Core: **text**, **speech**, or other **language**. Need not be fully novel research; should be **non-trivial / non-obvious** with data and/or algorithm.

#### Example Directions

- Known method(s) → **new dataset**  
- **New** method → **known** dataset  
- Paper algorithm → **new** domain or dataset  
- Descriptive NLP → practical or linguistic patterns  

#### Scope Expectation

Ambitious **2-3** person project ≈ **conference paper** experiments + depth.

#### Sources for Project Ideas

Past semesters; Stanford **CS224N** / **CS224D**; drive folder of top projects; recent **ACL** / **EMNLP** (and similar). Drive: **berkeley.edu** viewers only.

#### Example Project Ideas

- Abstractive news summarization  
- Menu extraction from reviews  
- QA with attention / memory  
- Image captioning  
- Gender / power in movie dialogue  
- Interpreting black-box / neural language models  

#### Conferences to Explore

**ACL**, **EMNLP** = top two; strong idea sources.

### Project Proposal

**Most important deliverable**; invest time. Concrete early idea → stronger project + course performance.

#### Submission Expectations

One proposal per group; **detailed feedback**. **200-300 words**; **quality >> length**.

#### What the Proposal Should Address

- What? Why important / hard?  
- Dataset(s)?  
- Algorithms? Off-shelf code vs own? (OK if thin early.)  

#### Required References

**≥4** papers tied to technique and/or dataset. Must be **research / technical pubs** of similar scope. Textbooks, docs, ref works -- **don’t count** toward four (still cite if used).

#### Suggested Resources for Finding Papers

ACL Anthology (start); ACM DL; SigKDD; WSDM; NIPS; ICML; Scholar; arXiv. Recent NAACL / ACL / EMNLP for “what’s hot.”

#### Support for Literature Search and Reading Papers

Week 2-4: OH sections on literature search + reading NLP papers; guided paper weekly; schedule + lists posted.

#### Submission Format

**Google Doc**; comment access for anyone with link; course form. **Inline** feedback. **No Word** uploads.

### Authors' Contributions (for Teams of 2 or 3)

**Required** section: enumerate each person’s work. Each **≥ one model**. Missing section or split violation → **point deduction**.

### Milestone (Optional)

Submit **milestone/interim** report **one week before** OH for structured feedback (email or OH).

#### What to Submit

**3-5 page** partial report + implementation. Include: data obtained / loaded / explored (EDA); **baseline** (random, majority, BoW, etc.).

#### Purpose of the Milestone Report

Working draft of final; results/conclusion may be thin; big pivots before final OK.

#### Suggested Milestone Write-Up Structure

Abstract; Intro; Background; Methods; Results/discussion (baseline+); **Next Steps** (replace in final with conclusions + full analysis).

#### Formatting and Writing Tools

LaTeX + ACL template common; or Word/Docs if **PDF** export.

#### Code Sharing Requirement

**GitHub** link.

#### Milestone submission (PDF)

PDF to course email or follow section instructor.

### Presentations

~**6 min** in **last** live week. Schedule + format announced later.

### Final Submission

**4-6 pages** (between ACL short and long paper).

#### Suggested Final Report Structure

Abstract; Intro; Background; Methods; Results/discussion (plots; vs baseline + literature); Conclusion.

#### Privacy Option

Opt out of public release in form.

#### Submission Instructions

PDF + code → course GitHub (solo) or team repo; complete form.

#### Important Final Deadline Policy

**No** post-deadline edits to report or submission body -- **late penalty**.

#### Feedback Timeline

Rubric feedback may lag **up to ~1 month** after deadline; term grades may post earlier.
